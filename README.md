# Peninsula

맥북 노치를 다이나믹 아일랜드로 만드는 macOS 앱. SwiftUI + AppKit, 외부 의존성 없음.

```bash
./scripts/bundle.sh release && open build/Dynamic.app
```

첫 빌드에서 [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter)(BSD-3)를 자동으로 받아 프레임워크로 빌드합니다. cmake는 필요 없습니다.

**유휴 CPU 0.1% · 메모리 18MB** — 전부 실측이고, 아래에 어떻게 거기까지 갔는지 적어 뒀습니다.

---

## 왜 반도(peninsula)인가

아이폰은 다이나믹 **아일랜드**입니다. 화면 한가운데 떠 있는 픽셀이라 진짜 섬이고, 마음대로 키울 수 있습니다.

맥북 노치는 **패널에 뚫린 물리적 구멍**입니다. 베젤에서 떼어낼 수 없습니다. 그래서 이 앱은 섬을 흉내 내지 않고, 붙어 있는 채로 뻗어 나가는 쪽을 택합니다 — 컷아웃과 **똑같은 검정**을 컷아웃 경계에서 시작해 자라나게 그리면 시각적으로는 동일해집니다.

그게 성립하려면 두 가지가 반드시 지켜져야 하고, 코드 전체가 그 두 규칙 위에 서 있습니다.

**1. 쉬는 상태는 컷아웃과 정확히 같아야 한다.**
상태가 넷입니다 — `idle`(컷아웃 그대로, 안 보임) / `compact`(양옆으로 조금 자람) / `peek`(배너) / `expanded`(전체). 알약을 항상 컷아웃보다 넓게 두면 "노치"가 아니라 "검은 막대"가 됩니다. 재생이 멈추고 일정 시간이 지나면 알약이 걷히고 노치만 남습니다.

**2. 컷아웃 위에는 아무것도 그리면 안 된다.**
카메라 하우징 뒤는 화면이 아닙니다. 그래서 컷아웃 위도(緯度)를 지나는 모든 행은 **leading / gap / trailing**으로 쪼개집니다 — 배너도, HUD 바도, 탭 줄도. 탭이 세 개가 되어 라벨이 안 들어가면 잘라내지 않고 아이콘만 남깁니다.

그리고 노치는 **비공개 윈도우 서버 Space에 고정**됩니다. `.stationary` 플래그만으로는 데스크탑 전환을 못 버티고, 패널이 같이 미끄러지면 물리 컷아웃이 그대로 드러납니다. 실제 노치는 하드웨어라 움직이지 않으니까요.

## 모션 — 추측하지 않고 측정했습니다

Apple이 WWDC23에서 정한 표기(`duration` + `bounce`)를 그대로 씁니다. 전환 하나는 [`Motion.Timeline`](Sources/Dynamic/Motion/Motion.swift) 한 곳에 정의되고, **실제 애니메이션과 모션 실험실이 같은 값을 읽습니다.**

기본 프리셋의 숫자는 고른 값이 아니라 **실제 다이나믹 아일랜드를 50fps로 녹화해 프레임마다 실루엣을 뽑고, Apple 자신의 `Spring(duration:bounce:)`을 최소자승으로 맞춘 결과**입니다.

| | duration | bounce | 적합도(rms) |
|---|---|---|---|
| 확장 · 가로 | 0.445s | +0.10 | 0.009 |
| 확장 · 세로 | 0.420s | +0.06 | 0.011 |
| 축소 · 세로 | 0.455s | +0.12 | 0.007 |
| 축소 · 가로 | ~0.19s | 과감쇠 | — |

여기서 두 가지가 뒤집혔습니다.

**확장할 때 두 축은 같이 움직입니다.** 폭이 먼저 퍼지고 높이가 따라온다는 건 그럴듯한 추측이었지만 틀렸습니다. 실측하면 가로·세로 진행률이 전 구간에서 2% 안쪽으로 붙어 다닙니다.

**축소할 때는 폭이 2배 이상 먼저 도착합니다.** 패널이 거의 즉시 가로로 오므라들어 세로로 긴 검정 블록이 되고, 그게 위로 빨려 들어갑니다. 맥북에서는 이게 "슬롯으로 되돌아간다"로 읽힙니다.

**내용은 재배치되지 않고 통째로 스케일됩니다.** 이것도 실측입니다. 확대 중 앨범아트의 왼쪽 여백을 프레임마다 재보면 컨테이너 폭 85.5%일 때 55px, 94.5%일 때 61px, 98.6%일 때 64px입니다 (최종 65px). 여백이 고정이면 계속 65여야 하는데, 컨테이너에 비례하면 55.6 / 61.4 / 64.1 — **비례합니다.** 그래서 각 상태의 내용을 자기 최종 크기로 한 번만 배치하고, 컨테이너의 두 스프링으로 스케일합니다. 매 프레임 그 크기에 맞춰 재배치하면 624pt 레이아웃이 384×101 상자에 눌려 행이 겹치고 모서리 밖으로 삐져나옵니다.

스케일은 반드시 **전환(transition) 안에** 있어야 합니다. 컨테이너 크기는 내용이 삽입되는 것과 *같은 트랜잭션*에서 바뀌고, 한 프레임 전에 존재하지 않던 뷰는 `.animation(_:value:)`가 비교할 이전 값이 없어서 조용히 아무것도 하지 않습니다 — 내용이 알약 안에 원본 크기로 나타납니다.

**흐림은 불투명도와 다른 시계를 씁니다.** 같은 곡선에 묶으면 흐림이 일정하게 걷혀서 "가장자리가 부드러운 크로스페이드"가 됩니다. 레퍼런스는 컨테이너가 30% 지날 때부터 초점을 잡기 시작해 75% 지점에서 이미 선명하고, 나갈 때는 **두 프레임 만에** 읽을 수 없게 됩니다. 그래서 흐림만 따로 `contentFocus` / `contentDefocus` 곡선을 탑니다.

반동은 여전히 **가로 전용 임펄스**가 담당합니다 — 컨테이너 스프링은 두 축에 같이 걸려 세로까지 떨리기 때문입니다. 임펄스는 t=0이 아니라 **폭이 도착하는 순간**에 들어갑니다.

### 모션 실험실

설정 › 모션 실험실에서 **1/60초 단위**로 앞뒤로 넘기며 매 프레임을 볼 수 있습니다. 추상적인 상자가 아니라 **진짜 아일랜드 내용**(앨범아트·제목·미터·스크러버·트랜스포트)이 실제 전환 효과를 그대로 받고 있어서, 요소가 언제 어떻게 도착하는지 눈으로 판정할 수 있습니다. 컷아웃 오버레이를 켜면 세이프존 침범도 바로 보입니다.

컨택트 시트로 뽑아 검토할 수도 있습니다:

```bash
"$(swift build --show-bin-path)/Dynamic" --dump-frames ./frames
```

## 기능

**재생 중** — 앨범아트(곡이 바뀌면 3D 플립), 제목/아티스트, 동기화 가사, 스크러버(남은 시간 −표기), 별·이전·재생·다음·AirPlay, 시스템 볼륨, 미터. 가사는 쉬는 상태의 알약에도 상시 표시됩니다.

**선반** — 화면 위쪽 넓은 띠에서 드래그를 잡고 패널이 활짝 열립니다. **AirDrop : 선반 = 1:3** 두 구역으로 나뉘어 놓는 위치가 곧 목적지입니다. 파일은 앱 전용 폴더로 복사되므로 원본을 옮겨도 유지되고, 같은 파일을 다시 놓으면 맨 앞으로 옵니다. 더블클릭하면 Quick Look, ×로만 삭제됩니다.

**기기** — 연결된 블루투스 기기 배터리. 에어팟은 좌/우/케이스를 따로 봅니다.

**라이브 알림** — 충전 연결/완료/부족, 다운로드·스크린샷 완료, 기기 연결, 집중 모드 전환.

**HUD 대체** — 볼륨·밝기 키를 가로채 시스템 오버레이 대신 노치에 표시. 손쉬운 사용 권한이 필요하고, 권한을 준 순간 재실행 없이 스스로 켜집니다.

## 성능

메뉴바 상주 앱이라 유휴 비용이 전부입니다. 실측하고 고쳤습니다.

| | 이전 | 지금 |
|---|---|---|
| 유휴 CPU | 4.2% | **0.03%** |
| 메모리 (physical footprint) | 57MB | **20MB** |
| 메모리 peak | 135MB | **20MB** |
| 확대/축소 중 CPU (프레임당) | — | **−25%** |

**① 미터가 CPU를 먹던 이유는 두 가지였습니다.**

macOS에서 `TimelineView`가 `NSHostingView` 안에 있으면 `sizeThatFits()`가 실제 크기와 0 사이를 초당 수십 번 진동하며 전체 레이아웃을 재계산합니다 (Apple FB13810482, 미해결). 노치가 정확히 그 구조입니다. 그리고 `.shadow()`가 컨테이너 전체에 걸려 있으면, 안에서 막대 하나만 움직여도 646×244 블러를 매 프레임 다시 계산합니다 — 그림자는 렌더링 *결과*가 드리우는 것이라서요.

미터를 `CAShapeLayer` + `CABasicAnimation`으로 바꾸고(보간은 렌더 서버가, 앱은 초당 4회 목표값만), 그림자를 콘텐츠 뒤 정적 레이어로 분리했습니다. **여기서 얻은 규칙: 애니메이션 요소를 그림자·클립이 걸린 레이어 안에 두지 말 것.**

**② 메모리는 앨범아트였습니다.** `NSImage(data:)`는 원본 해상도로 비트맵화합니다 — 3000×3000이면 픽셀만 36MB인데 화면에는 96pt로 그립니다. `CGImageSourceCreateThumbnailAtIndex`로 바꿔서 전체 비트맵이 애초에 만들어지지 않게 했습니다.

**③ 전환 중 비용은 세 군데였습니다.** 확대/축소를 200회 자동 반복하는 벤치(`DYNAMIC_BENCH=transitions`)를 만들어 부품을 하나씩 꺼가며 재봤습니다.

- **젤리 변형을 뷰가 아니라 도형에 겁니다.** `scaleEffect`를 컨테이너에 걸면 그 변환이 안에 있는 AppKit 뷰(미터·AirPlay 버튼)까지 내려가고, 매 프레임 `-[NSView setFrameTransform:]` → 오토레이아웃 무효화 → 트래킹 영역 갱신이 재귀로 돕니다. 4.4%p였습니다. `NotchShape`의 path를 늘리면 같은 모양에 비용은 사실상 0입니다.
- **보이지 않는 검정을 두 번 칠하고 있었습니다.** 그림자 레이어가 이미 같은 실루엣을 검정으로 채우는데 콘텐츠 레이어가 한 번 더 칠했습니다. 5%p.
- **외곽선은 안 보일 때 선 굵기를 0으로 둡니다.** `stroke`는 매 프레임 베지어 외곽선을 새로 계산합니다.

여기서 얻은 두 번째 규칙: **애니메이션되는 변환 안에 AppKit 호스팅 뷰를 두지 말 것.**

**④ 설정 창은 닫으면 놓아줍니다.** `isReleasedWhenClosed = false`에 static 참조까지 잡혀 있어서, 한 번 열면 SwiftUI 트리 전체가 세션 내내 남았습니다. 이 앱 상주 메모리의 대부분이 아무도 보지 않는 창이었습니다.

**⑤ 집중 모드 권한 조회를 캐시합니다.** `INFocusStatusCenter.authorizationStatus`는 프로퍼티 읽기가 아니라 `tccd`로 가는 **동기 XPC 왕복 두 번**입니다. 8초마다, 그리고 앱을 전환할 때마다 메인 스레드를 막고 있었습니다.

## 보안

**entitlement는 두 개뿐입니다** — 샌드박스 해제(perl 실행과 사용자 파일 복사), Apple 이벤트(음악 즐겨찾기). `allow-jit`과 `disable-library-validation`은 넣었다가 실제로 없어도 동작하는 걸 확인하고 뺐습니다.

**밖으로 나가는 데이터는 곡명·아티스트·앨범·재생시간 4개뿐**입니다. lrclib.net, HTTPS, 설정에서 끌 수 있고, 프로세스 전역 쿠키·자격증명을 들고 가지 않도록 ephemeral 세션을 씁니다.

**이벤트 탭은 키 입력을 볼 수 없습니다.** `NX_SYSDEFINED`만 구독하므로 손쉬운 사용 권한을 줘도 키보드·마우스·텍스트는 애초에 전달되지 않습니다.

**로그에 사용자 데이터를 남기지 않습니다.** 파일명·경로는 전부 `.private`으로 기록됩니다 — `.public`은 시스템 로그와 sysdiagnose에 평문으로 남습니다.

**비공개 API는 전부 `dlsym`으로 부릅니다.** `@_silgen_name`은 심볼이 사라지면 dyld 바인딩 실패로 앱이 실행조차 안 되지만, 이름으로 찾으면 `nil`이 되고 해당 기능만 조용히 꺼집니다. 전체 화면 위 표시(SkyLight), 밝기(DisplayServices) 둘 다 이 방식입니다.

**서브프로세스에 넘기는 패턴은 이스케이프합니다.** `pkill -f`의 인자는 정규식이고 시스템의 모든 프로세스와 대조되므로, 앱 경로에 `+ * ( [`가 있으면 무관한 프로세스를 죽일 수 있습니다.

## 알아둘 것

**재생 정보** — macOS 15.4부터 MediaRemote는 Apple 프로세스만 접근할 수 있습니다. [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter)를 통해, 아직 권한이 남아 있는 시스템 perl 바이너리로 읽습니다. 이 경로가 막히면 조용히 멈추지 않고 노치에 그 사실을 표시합니다.

**집중 모드는 읽기 전용입니다.** 켜고 끄는 공개 API가 없습니다. 상태가 보이려면 두 군데가 켜져 있어야 합니다 — 앱 권한(설정 › 기능 › 집중 모드)과 시스템 설정 › 집중 모드 › 집중 모드 상태.

**미터는 장식입니다.** macOS는 다른 앱의 출력을 읽는 공개 API를 주지 않습니다. 재생 상태에 반응할 뿐 신호를 측정하지 않습니다.

**서명** — 애드혹 서명은 빌드마다 서명이 바뀌고, macOS는 개인정보 권한을 서명에 묶습니다. 즉 **다시 빌드하면 권한이 조용히 사라집니다.** 번들러가 사용 가능한 인증서를 자동으로 찾아 쓰고, 직접 지정할 수도 있습니다:

```bash
SIGN_IDENTITY="Apple Development: you@example.com" ./scripts/bundle.sh release
```

**자동 실행**은 경로로 등록되므로 앱을 응용 프로그램 폴더로 옮긴 뒤 켜세요.
